HEALTHCARE OS · PUBLIC DEMO

Privacy notice

Prototype notice · Last updated 9 November 2026

Important: This is an early prototype notice, not a complete statutory privacy policy. Healthcare OS is not ready to collect real patient or sensitive health information. Use fictional information only.

1. The public demo

The interactive public demo uses fictional sample profiles, measurements, appointments, medication entries and notifications. Demo interactions are held in the current page session only. The demo script does not send those sample entries to the Healthcare OS API or Supabase and does not save them to an account.

2. Sign-in and existing accounts

The separate sign-in page connects to Supabase Auth for existing accounts. Account email addresses, authentication credentials and session information are processed by the authentication service. Depending on the “Keep me signed in” setting, the browser stores session state in persistent or session storage. New account registration is currently paused.

Signing in is separate from exploring the public demo. The authenticated workspace contains features that can store family and health-related information. Do not enter real patient information while this prototype's security, privacy, operational and legal readiness remains incomplete.

3. Password reset screening

When an authenticated user chooses a new password during account recovery, the server checks it against the Have I Been Pwned Pwned Passwords range service. The server sends only the first five characters of a SHA-1 hash to that service and compares the returned hash suffixes locally. The plaintext password is not sent to that service.

4. Hosting and technical information

Website pages and server requests are hosted through Vercel. The application also uses Supabase for authentication and its separate authenticated workspace. Hosting and infrastructure providers may process technical request information as part of operating and securing their services. This prototype notice does not specify provider retention periods or all possible infrastructure processing.

5. Cookies and browser storage

The sign-in experience uses browser storage to remember the session preference and, when selected, to maintain an authenticated session. The public demo's sample interactions are kept in page memory and are cleared when the page is reloaded or closed.

6. Sharing and sale

This notice does not claim that the complete authenticated workspace has undergone a production privacy assessment. No real health information should be submitted. Before any real-data launch, the operator must document all recipients, processors, retention periods, deletion processes and any applicable international transfers.

7. Your choices

You can leave the public demo at any time. If you are signed in to an existing account, use the account's sign-out control and avoid shared devices. Do not use this prototype to submit a request containing health information or identity documents.

8. Operator contact and future updates

The operator's legal identity, business address, privacy contact and formal data-rights request process have not yet been published. These details must be added and reviewed before the product collects real personal or health information. This notice will need a full legal and operational review before that point.

9. Prototype status

Healthcare OS is a care-coordination prototype, not a clinical service or medical device. This page is intended to explain the current demo boundaries; it is not a promise that the complete product is compliant with any particular privacy law.
